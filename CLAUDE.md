# Water Quality Forecasting — Project Instructions

Two independent efforts share this repo, with nothing in common beyond "don't commit regenerable
artifacts, and don't adopt complexity that doesn't earn its keep":

- **Root** — a baseline-vs-ML forecasting pipeline for NH4/COD/TSS four hours ahead at three Hanoi
  sites (Bay Mau, Cau Nga, Ho Tay), from 5-minute sensor logs recorded in 2024. Mature; see
  [README.md](README.md) for the full write-up.
- **[sbr-transition-transformer/](sbr-transition-transformer/)** — a separate, self-contained
  research subproject: a small transformer that detects SBR aeration phase-transition points
  ("ammonia valley", "DO elbow", "nitrate knee", "nitrate apex") from synthetic pH/ORP/DO sensor
  curves. Different task, different data, different dependencies (adds PyTorch). In progress —
  see its own README for scope and status.

The detailed rules below always apply, not only when asked.

## Mandatory rules (do not violate)

- **Nothing is adopted over `persistence` without proof.** Every forecasting model is scored
  against the rule *"in four hours it will be whatever it is now"* using a shared skill score
  (`1 − MAE_model / MAE_persistence`), and a positive skill score is not enough on its own —
  it must survive a paired bootstrap confidence interval (see `results/bootstrap_checks.csv`) or
  it's noise, not signal. An LSTM was tried and removed for failing this bar; don't re-add
  deep-learning complexity to the root pipeline without the same evidence.
- **Never hand-edit generated artifacts.** `cache/` (raw Excel parses, rebuilt by `01_eda.ipynb`),
  `processed/` (hourly tables, rebuilt by `02_data_preprocessing.ipynb`), and
  `models/candidates/` (every trained candidate, rebuilt by `03_model_training.ipynb`) are all
  gitignored and regenerated by rerunning the relevant notebook — don't patch them in place.
- **Never score on invented data.** The `is_real` mask flags every measured vs. filled/interpolated
  hour; evaluation must exclude filled rows, and any unbounded `interpolate()` call is a bug (it
  produced the spurious R² = −0.395 the README documents for Ho Tay's original LSTM run).
- **Splits are chronological, never random.** Oldest 85% train, newest 15% test — a model must
  never see the future relative to its own test rows.
- **`results/final_decision.csv` is the single source of truth for `forecast.py`.** Nothing about
  which model serves a given site/indicator is hard-coded; rerunning `04_evaluation_comparison.ipynb`
  and regenerating that file is how the deployed model changes.
- **`models/` holds only models that beat the baseline** (currently just
  `CAU_NGA_tss_gradient_boosting.pkl`); every trained candidate lives in gitignored
  `models/candidates/` instead.
- **Raw `.xlsx` sensor files are never committed** (`BAY MAU.xlsx`, `CAU NGA.xlsx`,
  `HO TAY.xlsx`) — place them at the repo root yourself to reproduce the pipeline from scratch;
  `04` and `05` can still run without them (see the README's "runs from a fresh clone?" table).
- **`sbr-transition-transformer/` is fully self-contained.** It has its own `requirements.txt`
  (adds `torch`), its own `.gitignore`, and its own README. Do not merge its dependencies into the
  root `requirements.txt` or edit the root README's "no deep-learning dependency is required"
  claim — that claim is about the forecasting pipeline specifically and stays true.
- **Update this file, and whichever project's own README, when a task changes a convention.**

## Project status

**Root forecasting pipeline:** complete and stable. Headline result: persistence wins 7 of 9
site×indicator cases; `gradient_boosting` wins Cau Nga/tss (+0.194 skill); `moving_average` wins
Ho Tay/tss (+0.173 skill). Working tree is clean on `main`; remote is
`github.com/Latherine/water-quality-forecasting` (private).

**`sbr-transition-transformer/`:** early implementation. `configs/default.py` (sim/model/train
config, disjoint seed blocks per split) and `data/landmarks.py` + `data/simulator.py`
(`SBRCycleSimulator`, generates synthetic per-cycle pH/ORP/DO curves with known landmark ground
truth) are done. Still to build: `data/features.py`, `data/dataset.py`, `model/` (transformer +
heatmap/pointer heads), `baselines.py`, `train.py`, `evaluate.py`, `tests/`, notebooks, and its own
`requirements.txt`/`.gitignore`/README — plus the verification sequence (baselines first, then a
tiny end-to-end run, then full-scale training). A draft project proposal for this subproject is at
`sbr-transition-transformer/docs/project_proposal.docx`.

## Commands

```bash
# Root forecasting pipeline
pip install -r requirements.txt
jupyter lab            # then run 01 through 05 in order
python forecast.py     # all nine forecasts at once, using results/final_decision.csv

# sbr-transition-transformer (once its own requirements.txt exists)
pip install -r sbr-transition-transformer/requirements.txt
pytest sbr-transition-transformer/tests/
python sbr-transition-transformer/train.py --config tiny   # fast sanity run before scaling up
```

## Environment

No CI, no `gh` CLI installed, and no PR gating — check `git status` before starting anything.
No `.venv`/`venv` currently exists in the repo (root `.gitignore` anticipates one under either
name, but neither has been created yet); the root pipeline only needs pandas, numpy, matplotlib,
scikit-learn, openpyxl, joblib, and jupyter (see `requirements.txt`).
